## 4. 第二阶段：按以下内容验收教学PDF

### 4.1 深度学习故障诊断

检查是否能让没有模型的初学者理解并走通完整流程：

1. 明确设备、故障类型、输入信号、标签、工况和研究问题。
2. 信号采集与基础检查：采样率、传感器、转速/负载、异常数据、采集记录。
3. 数据组织：先按设备或独立运行记录分组，再划分训练、验证、测试并在各组内切片；解释重叠窗口造成泄漏的风险。
4. 输入与预处理：原始波形、频谱、包络、时频图；标准化参数只由训练数据拟合。
5. 基础网络：从小型1D-CNN理解输入维度、卷积、激活、池化、分类层和输出。
6. 训练：损失函数、反向传播、优化器、学习率、batch、epoch、过拟合、验证集选模和检查点。
7. 评价：混淆矩阵、准确率、Precision、Recall、F1、类别不平衡、多次运行和独立测试。
8. 泛化与工程应用：噪声、工况变化、设备变化、域偏移及错误案例分析。

必须建立清楚的方法分类，避免将不同层次概念并列成一张“模型排行榜”：

| 层次 | 需要解释的概念 |
| --- | --- |
| 网络结构 | MLP、CNN、RNN/LSTM、Transformer、自编码器、图神经网络 |
| 学习方式 | 监督、无监督、半监督、自监督、迁移、元学习 |
| 泛化问题与设定 | 域适应、域泛化、小样本、开放集/未知故障；说明目标域数据和标签是否可见 |
| 特殊建模方法 | 神经算子与FNO、超网络、物理信息/物理约束方法 |
| 解释与验证 | 特征可视化、归因、可解释结构、消融及干预实验 |

重点讲清：FNO属于神经算子方法，原始任务和输入输出与普通故障分类有何区别；超网络是生成另一网络参数的机制；“泛化”是研究目标或能力，不能笼统当作一个独立网络名称。分别说明适用问题、前置知识、与故障诊断的联系和不宜直接套用的情形。

检查“完整模型”是否覆盖整个实验系统：数据协议、预处理、网络、损失、训练配置、检查点、推理、评价、日志和环境，而不只是一段网络类定义。修改自己的模型时，应覆盖输入输出形状、参数量、计算开销、训练稳定性、公平基线、消融、随机种子和数据泄漏。

### 4.2 特征挖掘

检查是否按“是什么—为什么有用—怎样做—怎样判断”讲解：

- 时域统计：均值、RMS、方差、峭度等，注明量纲和异常值敏感性。
- 频域：FFT、分辨率、窗函数、频谱泄漏、谐波和边带。
- 包络与解调、STFT/CWT时频表征、阶次分析的使用条件。
- 模态分解和冲击增强：VMD、FMD、MCKD/MOMEDA等的作用、参数和局限。
- 特征筛选、降维、聚类和模型内部表示；区分人工特征、自动特征学习与事后归因。
- 特征有效性的检验：故障相关性、稳定性、冗余、跨工况表现及混杂因素。

只需与用户研究相关的入门深度；不要堆砌算法名。轴承故障频率、柴油机工作事件、喷油器异常等必须按设备机理区分。

### 4.3 深度学习与特征挖掘结合

至少明确三条不同路线：

1. 训练并冻结模型，再用Grad-CAM、SHAP/CS-SHAP等解释。
2. 在网络设计中引入小波、时频变换或物理含义。
3. 将信号分解/特征增强与分类联合训练。

为用户最关心的第一条路线，检查是否给出可落实的研究顺序：定义问题 → 训练基线 → 独立测试 → 提取归因或表示 → 与故障机理对照 → 对照干预 → 跨工况检验 → 分析局限。

必须区分三个评价目标：预测性能、解释对模型的忠实程度、解释与物理机理的一致性。t-SNE聚类图、注意力图或漂亮热图不能单独证明模型正确。建议使用已知真值模拟信号、重要/不重要/随机区域干预、结构消融和独立工况验证，并讨论不合理扰动形成分布外信号的问题。
