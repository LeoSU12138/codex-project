
## 深度学习与特征挖掘结合

从“提出诊断模型”到“检查模型学到了什么”。

你想找的文章确实有：有的先设计可解释诊断网络，再分析学习到的滤波器或原型；有的在模型训练后用归因分析；还有的把信号增强和分类联合训练。它们支持的结论并不完全一样。

| 路线 | 典型工作 | 更适合回答 |
| --- | --- | --- |
| A 先训练，再解释 | CS-SHAP、Multilayer Grad-CAM、Mey与Neufeld。 | 固定模型主要依赖什么输入信息？ |
| B 在结构里加入信号知识 | TFN、WaveletKernelNet、Chirplet-CNN、FAM。 | 可学习计算能否与频带/小波等概念关联？ |
| C 提取与诊断联合优化 | ClassBD、BearingNet；MCNBD侧重冲击模态提取。 | 学习的信号处理能否保留/增强任务相关成分？ |
| D 用原型展示类别 | Prototype-matching。 | 模型认为典型故障频谱长什么样？ |

> 建议你的第一条研究路线：小型CNN基线 → 冻结模型 → 频带/时间片解释 → 随机和物理对照 → 如有需要，再据此设计新模块。

本册第2–3页讨论证据和文献；第4–6页给出实验流程；第7页讲模型修改；第8–9页提供阅读/写作检查单；末尾列出C01–C11参考来源。所有方案是教学建议，不是已获得的实验结果。


## 01  “正确”必须拆成几个问题

测试准确、解释忠实、物理一致，是互相关联但不同的证据。

| 问题 | 需要的证据 | 一句恰当结论 |
| --- | --- | --- |
| 是否预测得准？ | 独立分组测试、各类指标、错例。 | 在指定独立数据上达到所报告的识别性能。 |
| 解释是否反映模型？ | 遮蔽、随机带对照、参数/标签随机化。 | 这些频带对当前模型输出有实质影响。 |
| 解释是否符合机理？ | 特征频率/阶次、谐波侧频、工况规律。 | 模型的部分依据与已知机理一致。 |
| 能否提取故障成分？ | 已知源模拟、残差检查、外部传感器/干预。 | 候选分量保留了可验证的故障相关成分。 |
| 能否适应新场景？ | 未知设备/工况/噪声，锁定开发协议。 | 在这些额外条件下仍有一定有效性。 |

### 为什么单靠热图不够？

模型可能利用“故障样本总是在较高转速采集”这个捷径。热图标出转频时看起来很合理，却没有真正区分故障。要在同工况下比较正常和故障，并在跨工况数据中检验这种线索是否仍然有效。

> 更好的论文表述：“通过独立测试、扰动对照和故障特征频率分析，为模型的判别有效性及部分决策依据提供支持。”避免写成“特征挖掘证明模型绝对正确”。

依据：融合文献C10的模拟/转速对照思路；特征册F10的随机化检验。具体实验应适配你的任务。

## 03  最小可行研究：先有基线

推荐任务：已知转速和采样率条件下的轴承闭集分类。

| 工作 | 产出 | 关键约束 |
| --- | --- | --- |
| 明确标签 | 正常/内圈/外圈等定义与来源。 | 不要把不同严重度或采集位置混为同一条件。 |
| 建立数据协议 | 原始文件、轴承、工况、集合归属。 | 先独立分组后切片；测试集锁定。 |
| 简单基线 | 时域/频域特征+传统分类器。 | 检查深度网络是否真的提供增益。 |
| 深度基线 | 两三层1D CNN+全局池化+分类头。 | 记录张量形状和窗口的物理时长。 |
| 训练与选择 | 训练日志、验证标准、最终checkpoint。 | 不按测试表现选择epoch。 |
| 最终预测评估 | 混淆矩阵、macro-F1、各类召回率。 | 包含错误样本和每组结果。 |

### 解释模型前先排除程序错误

检查标签编码、采样率、单位、标准化统计量和训练/评价模式。用少量样本检查模型能否拟合训练数据只是调试；若连调试都失败，先修数据或实现，不要急着解释热图。

> 如果CWRU可用独立轴承不足以支持所需三分组，就降低结论范围或更换数据。不能把一条记录的窗口分到三组，再称跨轴承验证。


## 04  冻结模型后怎样挖掘

每一次解释都应有一个明确问题和预先定义的分析对象。

### 研究问题示例

“模型对内圈故障的高分，是否主要依赖包含周期冲击调制的共振频带？”这个问题比“画一张SHAP图”更具体，也允许得到否定结果。

| 步骤 | 你要固定的选择 |
| --- | --- |
| 选样本 | 从预定分析集分层抽样：每类、每工况都包括；包含错判样本。 |
| 选目标 | 内圈故障logit或其他指定输出；记录真实类与预测类。 |
| 选表示 | 时域、频域、包络域或循环谱域；先从便于验证的一种开始。 |
| 选解释器 | IG、频带遮蔽或CS-SHAP；先检验其输入接口与变换一致性。 |
| 选基线 | 来自训练数据的合理背景；对多个背景重复评估。 |
| 做汇总 | 分开统计正确/错误、类别、工况；报告样本分布与不确定性。 |

如果分析结果用于改变频带或结构，它就属于开发过程，必须在训练/验证范围内完成。最终测试数据可以用于预定的报告性分析，但看过后再修改方案，就不能继续称它为未见测试集。

> 先分别展示：输入信号、模型预测、归因图、选定频带处理后的信号。对“从哪一步得到什么结果”保持清楚，避免把解释图当作提取出的物理波形。


## 05  必做的对照实验

以下矩阵是实验设计模板，未包含任何实测性能。

| 对照 | 保持一致的内容 | 要观察的差别 |
| --- | --- | --- |
| 重要/不重要/随机带 | 相同带宽和处理，尽量匹配能量。 | 重要带干预是否比低归因带和随机带改变输出更多。 |
| 保留重要带 vs 保留随机带 | 保留带宽与信号重构流程。 | 重要带是否保留更多任务信息。 |
| 已训练 vs 随机参数 | 同样输入、解释方法与显示尺度。 | 解释是否依赖学到的参数。 |
| 真标签 vs 打乱标签重训 | 相近训练预算与拟合检查。 | 解释是否依赖有意义的标签结构。 |
| 真实信号 vs 已知源模拟 | 使用一致的信号处理和坐标定义。 | 能否定位已知注入成分，是否误标干扰。 |
| 源工况 vs 未见工况 | 固定解释设置与模型选择规则。 | 依据及性能是否随工况失效。 |

### 指标分开报告

诊断报告macro-F1、召回和误报；解释报告分数变化、删除/保留曲线及稳定性；物理报告真值定位或机理频率一致性。容差在验证阶段确定。遮蔽可能产生分布外信号，须检查相位、能量和边缘，比较合理替换；分数下降不自动证明故障因果。

> 删除实验观察的是固定模型的依赖。用所选特征重训一个新模型，观察的是特征集的可用性。这两类实验都可做，但不能混为一谈。


## 06  何时值得修改模型

先说明基线哪里失败，再选择一个模块。

| 观察到的问题 | 可检验的改进假设 | 必要消融 |
| --- | --- | --- |
| 频带选择不稳定 | 参数化时频/小波层可能限制无关自由度。 | 普通卷积 vs 参数化层；相近参数量。 |
| 工况变化影响很大 | 显式工况条件或阶次对齐可能改善。 | 普通模型、条件拼接、超网络分别比较。 |
| 噪声掩盖冲击 | 盲解卷积/去噪模块可能增强周期成分。 | 无模块、仅分类损失、联合损失。 |
| 长期依赖未捕获 | 增大感受野或引入时序模块可能有效。 | 先加大普通卷积，再比较复杂模块。 |
| 归因与机理冲突 | 可能是标签/采集混杂，应先修数据协议。 | 同工况控制、去除泄漏、重新独立测试。 |

不要只因为FNO、超网络或Transformer名字新就替换CNN。需要明确它解决的是表示、条件化、全局依赖还是函数映射；还要证明增加的计算代价值得。

### 三个版本足够开始

A：原始小CNN。B：只替换一个模块。C：容量相近的普通CNN对照。使用相同划分、调参预算和多种子，既看性能，也看解释与复杂度；负结果同样记录。

> 解释引导改进时存在循环论证风险：先在验证集发现规律，再在独立测试集检验。不能用同一批数据既挑依据，又宣称依据被独立验证。


## 07  读论文与复现记录表

每篇论文先填以下问题，不必一开始推导全部公式。

| 记录项 | 你要从论文或代码中找到什么 |
| --- | --- |
| 任务与输入 | 设备、类别、采样率、传感器位置、窗口长度。 |
| 独立性 | 划分单位是窗口、记录、轴承还是设备？训练与测试有无重叠来源？ |
| 模型与目标 | 核心新模块、输入输出、损失项和各项权重。 |
| 声称的创新 | 改结构、改训练、改解释，还是改信号提取？ |
| 验证方式 | 分类指标、消融、泛化、解释忠实性、物理对照各有什么？ |
| 复现资源 | 作者代码、数据来源、依赖、配置、预训练权重是否齐全？ |
| 你的最小复现 | 先复现哪一个图/表/数据子集；需要多少算力和修改？ |
| 局限与失败 | 未知工况、其他故障、负结果、代码缺项、不能访问的数据。 |

### 复现可以分三层

① 跑通：程序产生输出。② 数值复现：相同协议下性能在合理差异范围内。③ 结论复核：换独立划分或外部数据后，核心结论仍获支持。本资料只核验资料与入口，未完成这三层实验。

建议先做C06的模拟演示，再做C01的真实数据基线；若依赖不兼容，记录修改前后的版本和数值变化，不要悄悄替换后仍称完全一致。


## 08  最后形成什么研究成果

把模型、证据、限制按一条完整逻辑组织起来。

| 部分 | 至少回答一个问题 |
| --- | --- |
| 问题 | 现有模型在什么具体场景下不足？ |
| 方法 | 你改变了哪个计算环节，为什么预期它有帮助？ |
| 诊断实验 | 独立数据是否支持预测能力提高？ |
| 特征分析 | 模型主要依赖什么，解释是否对模型敏感？ |
| 物理分析 | 这些依据如何随转速/负载变化，与机理哪里一致或不一致？ |
| 限制 | 哪些数据、故障、设备和工况没有验证？ |
| 复现包 | 数据索引、配置、代码、日志、权重、图表脚本如何对应？ |

### 适合你现在的学习路径

第一阶段：深度学习册前8页，跑通简单分类。第二阶段：特征册前5页，理解波形、频谱、包络和特征表。第三阶段：特征册归因与检验，完成一个固定模型解释实验。第四阶段：本册对照矩阵与独立测试。最后才考虑新的模型结构。

> 你目前没有模型并不是障碍。第一个成功标准是：能清楚说明数据、划分、预测、依据和限制，并让别人重复得到同一套结果。
