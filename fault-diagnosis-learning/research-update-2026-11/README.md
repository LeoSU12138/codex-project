## 这次继续调研补了什么

一是把“解释好不好”拆成忠实度、稳定性、真值定位、随机化与机理一致性，并讨论频带替换、能量匹配和分布外伪影。二是定点检查CS-SHAP变换、patch贡献、背景、近似预算和缓存，明确复现时要保存的配置。三是核查跨域选模差别，避免将目标域参与调参的结果当作严格域泛化。四是补全时序结构、自监督、基础模型与物理建模的选型边界。

实际读取17份作者/工具README与3份源码；源码检查限于具体函数，未审计全部工程。Crossref、arXiv检索与两篇候选页面因代理403未取得内容；没有新论文全文或模型实验。本轮是定向研究补充，不能称穷尽检索或最新性能排名。既有38篇书目、31篇阅读子集和原始任务书保持原貌。

## 下一步先做什么

先选择设备与分类目标，填写[原始记录清单模板](data_manifest_template.csv)，确认可用的独立设备、运行记录、转速与负载。随后建立人工特征+浅层模型和小型CNN的公平基线，再进入解释。没有转速时不强做阶次结论；没有真实故障程度标签时不声称程度识别。

[实验协议模板](experiment_protocol_template.json)把待确定内容置为null，便于在实验前填写并冻结；[结果记录模板](experiment_results_template.csv)只有表头，未填任何性能值。这些是研究记录工具，不是可直接运行的训练框架。

## 构建与维护

从仓库根目录执行：

```bash
python fault-diagnosis-learning/src/build_research_update.py
python fault-diagnosis-learning/src/validate_research_update.py
```

需要Python、reportlab和PyMuPDF；已测试版本在交付验证记录中。生成器无网络请求，只读取已提交来源与Markdown。需要再次刷新固定来源时运行collect_sources.py；网络策略必须允许访问，失败要保留。重新读取可能改变上游正文与哈希，因此应同步人工更新证据说明和验证记录。

本轮采用literature-review技能组织检索与证据范围；[流程来源说明](来源与证据映射.md)保留历史流程引文及本轮未能重验的状态。
