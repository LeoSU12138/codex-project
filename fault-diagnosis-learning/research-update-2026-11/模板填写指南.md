# 从空模板到可复查的研究记录

2026-11-07新增，对应[首页六步路线](../../README.md)与[研究执行清单](研究执行清单.md)。模板用于记录研究，不会下载数据、切片、训练或计算指标。仓库内保留空模板；请在自己的副本填写，未知项写unknown或留空并在限制中说明，不能用0代替未知数值。

## 1. 先复制，再填写

从仓库根目录运行下面的Python代码，或手动复制同名文件。目标文件已存在时不覆盖。local-research目录已被Git忽略，用于个人记录和实验输出；需要分享时选择已整理的文档另行提交，原始数据按来源许可处理。

```python
from pathlib import Path
import shutil
source = Path('fault-diagnosis-learning/research-update-2026-11')
target = Path('local-research')
target.mkdir(exist_ok=True)
for name in [
    '研究执行清单.md', 'data_manifest_template.csv',
    'window_manifest_template.csv', 'experiment_protocol_template.json',
    'experiment_results_template.csv', 'feature_candidates_template.csv',
    'literature_review_template.csv',
]:
    destination = target / name.replace('_template', '')
    if not destination.exists():
        shutil.copy2(source / name, destination)
```

CSV为UTF-8编码，可用Excel/WPS编辑；保存时保留字段名，ID、哈希和路径按文本处理。JSON用文本编辑器填写：文本加双引号，列表用方括号，对象用花括号，待定值用null。旧版本模板的字段继续有效；本轮增加的字段见下面说明，旧副本可补列，保留原有数据。

## 2. 各步骤用哪个文件

| 步骤 | 填写文件（个人副本名） | 何时填写 |
| --- | --- | --- |
| 1 明确问题 | 研究执行清单.md、literature_review.csv | 先填项目卡；阅读时持续登记文献 |
| 2 数据与划分 | data_manifest.csv、window_manifest.csv、experiment_protocol.json | 先原始记录/组划分，再生成窗口，记录协议 |
| 3 基线 | experiment_protocol.json、experiment_results.csv | 先记录配置，训练后填真实结果 |
| 4 解释 | 同一协议和结果表 | 保存模型/背景/变换哈希及干预定义 |
| 5 特征与最终测试 | feature_candidates.csv、协议和结果表 | 训练范围发现、验证选参，锁定后最终测试 |
| 6 小结 | literature_review.csv、研究执行清单.md | 补全文证据、结论和下一步 |

所有相对路径建议相对于local-research目录；大型数组、权重、逐类指标另存文件，在表中填写路径。哈希指实际文件内容的SHA-256，不能用文件名或示例字符串代替。

## 3. 原始记录清单

下载：[data_manifest_template.csv](data_manifest_template.csv)。一行表示一条可追溯的原始采集记录；多通道可在channel中列出同步通道集合。拆为多行时，record_id须唯一，但同一运行相关记录应共享group_id，不能因拆文件/通道增加独立单位数。

| 字段 | 填写含义与检查 |
| --- | --- |
| record_id、group_id（本轮新增） | record_id是唯一记录ID；group_id是按任务定义的划分组，例如设备或运行，组内记录只能属于一个集合 |
| dataset、source_url、license | 数据集名称、来源入口和实际使用许可；来源未确认时如实写明 |
| file_path、file_sha256 | 原始文件路径与字节哈希；同文件的不同记录/通道可能共享哈希，不能仅靠哈希定义独立性 |
| machine_id、run_id、session_id、fault_entity_id | 设备、运行、采集批次和同一故障实体；未知则不臆造。多次测量同一损伤不是多件独立损伤 |
| condition_id、speed_rpm、load | 工况ID、转速及负载；转速单位rpm，负载在值或协议中说明单位。变转速可写轨迹文件路径并在协议定义解析方式 |
| sample_rate_hz、unit、sensor_location、channel | 采样率Hz、信号物理单位、传感器位置及通道顺序；重采样后的设置另外记录 |
| label、label_evidence | 标签及依据，例如人工缺陷记录、维修确认；预测标签不能冒充真实标签 |
| split、independence_notes | train/validation/test，未划分时pending；说明分组依据、依赖关系、缺失条件和无法支持的外推 |

先把该表的group_id分配给集合，再切片。若跨工况目标要求同设备出现在不同工况集合，须明确独立性限制；不能同时宣称跨设备。固定文件名可以帮助追溯，但不证明机器或标签真实。

## 4. 窗口清单与追溯

下载：[window_manifest_template.csv](window_manifest_template.csv)，本轮补充。由实际切片代码导出，一行一窗口，不建议大量手填。

| 字段 | 填写含义与检查 |
| --- | --- |
| window_id、record_id、group_id | 窗口唯一ID；后两项必须能关联原始表，group_id必须一致 |
| file_sha256、channel | 原始文件哈希和通道顺序，不能指向未记录的原文件 |
| start_sample、end_sample_exclusive | 以原始记录采样点为坐标，0开始，右端不包含；应为非负整数且end大于start |
| sample_rate_hz | 上述原始采样坐标对应的采样率；重采样另记，避免把新旧坐标混用 |
| split、preprocessing_version | 继承原始记录所属集合；处理配置/代码版本，包含重采样、滤波和标准化来源 |

**只作格式说明的虚构例子，不能当成真实数据或足够的实验设计：** R001/G001在train中，采样率12000 Hz；W001取[0,2400)，时长0.2秒，W002取[1200,3600)。两窗口重叠1200点，必须跟随原记录留在train；把W002放test会泄漏。跨记录是否独立仍需设备、批次和故障实体信息。

至少人工/程序核对：window_id唯一、record_id存在、集合与group一致、区间不越原始长度、同源重叠不跨集合。仓库的文件检查器只验证空模板和字段，不替你完成这些真实数据检查。

## 5. 实验协议JSON

下载：[experiment_protocol_template.json](experiment_protocol_template.json)。它是研究记录的结构，不是训练程序的配置接口。开发阶段可以迭代并保存版本；每次评价关联使用的协议版本。最终测试前锁定所有相关选择。

| 字段 | 建议类型与内容 |
| --- | --- |
| status、locked_at | 草稿副本可用draft，锁定后用locked并填写带时区时间；仓库模板保持template_not_executed和null |
| research_object、task | 文本：设备/应用与任务、类别定义 |
| data_manifest、window_manifest | 文本路径：原始记录与窗口清单；window_manifest为本轮新增 |
| feature_manifest、literature_review_manifest、test_usage_log | 本轮新增路径：候选特征、文献核验、测试查看日志；日志记录时间、目的、协议版本、是否修改方案 |
| independence_unit、uncertainty_unit | 文本：划分与统计的独立单位，例如machine或run，不能默认为window |
| source_domains、target_domain_access | 域列表及对象：目标域数据/标签分别是否可见、何时使用；严格DG与UDA分开 |
| split_hash | 锁定的原始记录/集合分配清单哈希，格式变化也会改变哈希，保持同一版本文件 |
| preprocessing | 对象：采样率、通道、窗口时长/步长、滤波、标准化拟合范围与参数文件 |
| model_baselines、hyperparameter_budget、training_seeds | 列表/对象：具体基线、每个方法调参次数与选择准则、种子列表；包含代码/依赖与权重保存位置 |
| explanation_target、background_source | 对象：目标类别ID/名称、logit或概率、层；背景来源、抽样规则及哈希 |
| grouping_and_patch、transform_and_reconstruction_checks | 对象：解释粒度、实际变换配置、重构误差指标和检查规则 |
| perturbation_control | 对象：重要/随机/低重要区域、替换策略、区域比例、随机重复数、能量/带宽等控制 |
| primary_outcomes、feature_selection_scope | 指标列表与选取范围；保留训练发现、验证选参、最终测试留出的原则 |
| decision_and_stop_rules | 文本/对象：何时进入下一阶段，什么结果否定假设，失败后如何处理 |

例如preprocessing中可分别保存window_seconds、stride_seconds、normalization_fit_split="train"与config_path。具体数值由设备、数据和验证确定，本指南不提供可直接宣称有效的默认配置。

## 6. 实验结果表

下载：[experiment_results_template.csv](experiment_results_template.csv)。一行表示某次运行、某种工况/集合/评价方法的结果；需要多个条件时使用多行，并给experiment_id可区分的后缀。未执行的指标留空，不能填预期成绩。

| 字段 | 填写含义与检查 |
| --- | --- |
| experiment_id、model_version、split_hash、seed | 唯一可追溯运行ID、代码/权重版本、划分哈希与真实种子 |
| evaluation_split、protocol_version（本轮新增） | 明确train/validation/test与实际协议文件/哈希；避免把验证成绩误当最终测试 |
| condition、evaluation_unit、independent_groups | 工况、评价单位、独立组数，后者不是窗口数或种子数 |
| macro_f1、per_class_recall_path | macro-F1统一用0到1，注明聚合规则；逐类召回与混淆矩阵文件另存 |
| target_output、attribution_method | 解释类别及logit/概率、方法/层；普通预测行可留空 |
| background_hash、transform_config_hash、patch_definition | 解释背景、变换配置哈希与粒度，确保能重算且不误用缓存 |
| perturbation_policy、random_repeats、fidelity_delta | 干预定义、随机重复数和比较值；fidelity_delta必须引用协议公式与方向，没有统一通用分数 |
| stability_metric、feature_budget | 记录指标名、数值与参数，或指向详细文件；特征维数/预算与对照一致 |
| runtime_seconds、artifact_path、limitations | 耗时及范围（训练/单样本解释等）、结果目录、异常/负结果/适用限制 |

模型、背景或预处理改变后，相关归因应重新计算或明确分列。多个种子不能当独立设备样本；检验与区间按实际独立单位进行。

## 7. 候选特征定义表

下载：[feature_candidates_template.csv](feature_candidates_template.csv)，本轮补充。每个feature_id对应一个有固定公式/参数的候选；修改定义就保存新版本。

| 字段 | 填写含义与检查 |
| --- | --- |
| feature_id、name、formula | 唯一ID、可读名称、可直接实现的公式；写清求和区间、分母、零值处理，不能仅写“深度特征” |
| input_domain、unit、parameters | 时域/频域/包络/阶次等、量纲及所有带宽/窗/归一化设置 |
| discovery_record_ids、selection_split、validation_selection_rule | 实际发现记录ID、选择使用的集合及验证规则；不得来自最终测试发现后包装成独立候选 |
| mechanism_hypothesis、control_features | 与机理相容的假设，以及同维度传统/随机特征对照 |
| frozen_at、implementation_version | 最终测试前锁定的时间和实现版本 |
| status、limitations | proposed/validated/frozen/rejected等真实进度及局限；validated必须写明是在何种开发验证下通过 |

例如“某训练选择频带的包络谱能量占比”必须明确带边界、谱估计、分母频带及采样率；后续测试沿用定义。该例子是研究建议，不代表仓库已发现有效频带。

## 8. 全文与引用核验表

下载：[literature_review_template.csv](literature_review_template.csv)，本轮补充。正式38篇题录用于定位，个人阅读记录用于判断你真正核验了哪些主张；无需修改原始历史快照来记录个人阅读。

| 字段 | 填写含义与检查 |
| --- | --- |
| entry_id、catalog_namespace | 如C06及research-papers；旧库用references，新增线索用candidate，不能只记编号 |
| doi_or_url、title、version、checked_on | 可核对入口、完整题名、期刊/预印本版本、真实核验日期 |
| retrieved_level | metadata/abstract/readme/selected_code/full_text/not_retrieved；使用论文题录不等于已读全文 |
| claim_to_support、source_location | 你希望引用的具体主张，以及原文页码/节/表/图；README写对应段落，不能填论文页码 |
| data_and_split、reported_result、limitations | 原文设备/工况/独立划分、实际报告结果和限制；看不到的信息写未确认，自己的建议另记 |
| code_data_status、citation_use、open_question | 代码/数据入口与核验范围，引用用途，剩余疑问/失败原因 |

读不到全文就保留限制，不编造实验条件。两篇候选与C12出版状态可在此列为待核验；网络失败不是“论文不存在”。阶段小结要同时列支持证据、反例与未解决项。

## 9. 每次阶段结束前检查

记录能否从结果行找到协议、权重、预处理、原始记录与划分？特征是否有固定公式和发现范围？文献结论是否有可回到原文的位置？若任一项缺失，先补记录，再扩大模型或方法数量。个人进度写回执行清单；阅读材料的生成/验证脚本不应被当成训练命令。
