## 第1步：确定问题与最少阅读

- [ ] 填完项目卡，明确一个设备、一个任务、一个首要问题。
- [ ] 能区分训练/验证/最终测试；能区分分类性能、解释忠实度与物理一致性。
- [ ] 按需读三册入门，知道当前信号应看波形、频谱还是包络。
- [ ] 在literature_review.csv先登记与你的问题直接相关的核心文献，未读的保留“待读”。

完成标志：得到问题卡与待解决的数据条件。若设备/标签仍不明，先查数据和机理，不把模型名称当研究问题。通过后进入第2步。

## 第2步：数据追溯与独立划分

- [ ] data_manifest.csv逐行对应原始记录；record_id唯一、group_id按研究独立单位定义。
- [ ] 保存数据来源、许可、标签依据、文件哈希、采样率、单位、转速/负载的缺失情况。
- [ ] 先按组划分，再切片；window_manifest.csv记录0起点、右端不包含的原始采样区间。
- [ ] 同组只属于一个集合；同一原始文件的重叠窗口未跨集合。设备身份未知就不声称跨设备验证。
- [ ] 检查波形、频谱、包络、异常值和单位，标准化只拟合训练数据。
- [ ] 在experiment_protocol.json记录划分哈希、预处理和最终测试用途，尚未满足条件的字段列入缺口。

完成标志：清单可追溯、划分与任务相符、没有明显泄漏。独立组不足时缩小任务或采用明确的分组验证设计，不能靠更多窗口补成更多设备。通过后进入第3步。

## 第3步：两个公平基线

- [ ] 从作者工程或自建实现开始，核对依赖、标签映射和数据加载；保存代码版本。
- [ ] 完成人工特征+浅层分类器和小型1D-CNN；两者使用相同划分和可比的调参预算。
- [ ] 验证集选参、早停与选模；保存模型、标准化参数、日志、种子和错误案例。
- [ ] experiment_results.csv明确evaluation_split与protocol_version，逐类召回保存在关联文件中。
- [ ] 核查多数类基线、标签与工况混杂；区分窗口数、记录数、设备数和训练种子。

完成标志：两个基线可重复，结果足以判断模型是否学到诊断信息；无须预设99%门槛。失败时先修数据、协议或实现。通过后进入第4步，最终测试仍保留。

## 第4步：冻结解释与对照

- [ ] 固定权重、类别、logit/概率、解释层、背景及预处理；梯度归因保留自动微分。
- [ ] 先做IG/Grad-CAM；按需加入频域SHAP/CS-SHAP，记录变换、patch、预算与缓存版本。
- [ ] 在训练/验证范围开发；比较重要、低重要、随机区域，并检查带宽/能量与扰动伪影。
- [ ] 做背景/种子敏感性和参数随机化检查；有真值模拟时单列定位结果。
- [ ] 正确与错误预测均检查；把模型依赖与机理假设分开写。

完成标志：有原始归因、对照和失败案例，能说明证据支持到什么范围。若只有好看的图，继续查解释设置；不要直接把它用于机械因果结论。通过后进入第5步。

## 第5步：候选特征与一次最终评价

- [ ] 在feature_candidates.csv保存公式、单位、参数、发现记录、验证选参依据和机理假设。
- [ ] 用相同维度、分类器、预算与划分比较传统、随机、候选特征；随机对照重复抽取。
- [ ] 锁定模型/特征/解释/指标，更新protocol版本与locked_at，才启动最终测试。
- [ ] 预定的性能、解释和跨工况评价统一报告；记录测试查看时间、目的及是否据此改动方案。
- [ ] 记录独立组级结果/适当不确定性，区别种子波动和数据独立性。

完成标志：独立对照支持或否定假设，并保留无收益结果。查看测试后再改进需另设未见验证；原测试只能作为已见数据，不能重新包装成最终独立证据。通过后进入第6步。

## 第6步：形成小结与下一项研究

- [ ] 核验核心全文和正式版本，literature_review.csv记录支持主张的原文位置、数据/划分和限制。
- [ ] 把来源主张、自己的观察、建议和未验证假设分开。
- [ ] 汇总问题、方法、对照、结果、成本与局限；只对实际覆盖的设备/工况作结论。
- [ ] 提出一个由失败案例驱动的下一步，而不是同时添加多个新模块。
